# TransferLab — решение о публичном Beta (момент X)

> Статус автоматически определяется `scripts/beta_readiness.py` по собранным данным.
> Публичный отчёт: `/beta.html`, машиночитаемые проверки: `/data/beta_readiness.json`.
> Нельзя вручную ставить статус «готов» или заменять отсутствующие данные нулями.

## Фиксируем объём Beta

Beta включает поиск по каталогу, профиль игрока, сезонную/турнирную статистику,
оценку TransferLab с явной неопределённостью, Hidden Gems с раздельным
подтверждённым/архивным статусом, историю сделок и экспорт отчётов.
Дизайн и новые «красивые» фичи не являются блокирующими, пока не мешают этим задачам.

## Пять проверяемых требований

1. **Каталог:** не менее 10 000 разных ID футболистов без выдуманных профилей;
   клуб/контракт из архивного датасета должны быть маркированы архивными,
   а отсутствующая статистика не превращается в 0.
2. **Полнота статистики:** не менее 90% детерминированной выборки 1000 игроков
   (отбор по реальным минутам последнего полного сезона) должны иметь
   подтверждённые матчи, минуты, голы и ассисты **за текущий сезон**.
   Данные xG, обводок и отборов считаются только по подтверждённому покрытию;
   отсутствие источника отмечается «нет данных».
3. **Проверка стоимости:** не менее 100 переходов с прогнозом TransferLab,
   который действительно был записан **до** сделки (не более 45 дней).
   Предварительный порог медианной абсолютной процентной ошибки — 40%.
   Сделка ≠ рыночная стоимость, поэтому нужен анализ по позициям, лигам и
   структуре бонусов, а не только одна итоговая ошибка.
4. **Hidden Gems:** минимум 30 кандидатов с проверенными текущими матчами,
   клубами и разрешёнными к использованию свежими рыночными ценами;
   затем отдельно подтверждается их позиционное сравнение с ≥25 аналогами.
   30 кандидатов с данными — необходимый, **но недостаточный** критерий 30
   действительно недооценённых игроков.
5. **Надёжность:** 7 последовательных календарных дней успешных автоматических
   проверок. Это не подмена независимого мониторинга доступности:
   внешний 7-дневный uptime-отчёт — отдельное условие полного коммерческого запуска.

## Проверка индекса — до изменения коэффициентов

- Изменения формулы принимаются для *всех* игроков одной роли, не по именам
  «Нуну» или «Хакими».
- Сравнение контрольных сезонов без информации из будущего.
- Покрытие защитных событий и xG/90 показывается по матчам, где метрика измерялась.
- Любой новый коэффициент сопровождается версией модели и regression-тестом.
- Ошибки на выборке сравниваются с прошлой моделью; «стал похож на экспертное
  мнение» само по себе не является доказательством улучшения.

## Происхождение и права

- Transfermarkt-derived архив июля 2026 года можно использовать как
  исследовательский исторический срез только после проверки соответствующих
  разрешений на использование. Это **не live-данные**.
- Дата истечения исторического контракта — не подтверждение действующего
  контракта; известные актуальные сроки имеют отдельный источник.
- «Подтверждённая находка» требует правомерного источника актуальной цены.
  Прогноз TransferLab **не является независимой рыночной оценкой**.
- Фотографии публикуются лишь при подтверждённом разрешении/лицензии.
- При ошибке источника интерфейс показывает отсутствие данных, а не
  несуществующие матчи/цены.

## Обязательный цикл выпуска

1. GitHub Actions обновляет доступные источники без подмены дат.
2. Запускаются parser/unit/aggregation/JS/browser tests на десктопе и телефоне.
3. Публикуются `/data/coverage.json`, `/data/hidden_gems_verification.json`,
   `/data/forecast_backtest.json`, `/data/beta_readiness.json`.
4. Снимок модельных цен на дату/коммит сохраняется для **будущих** переходов.
5. Публичный `/beta.html` показывает пройденные и заблокированные критерии.
6. После 7 дней проверки — пилот с 30–50 пользователями; затем проверка
   возвращаемости и платного спроса (≥5–10 регулярно возвращающихся пользователей).

## Не обещаем

Не заявляем «контракты и актуальная статистика у всех 10 000», 100 точных
прогнозов прошлых сделок, «30 подтверждённых Hidden Gems» и 7-дневный uptime,
пока нет подтверждающих данных. Сборка сайта может быть зелёной при статусе
`not_ready`: технический деплой и продуктовый запуск — разные решения.
