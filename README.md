# TransferLab

Футбольная аналитика и экспериментальная модель оценки трансферной стоимости.

**Состояние проекта:** сборка TransferLab 5.0 из архивного ZIP, 1 353 профиля / 11 лиг. Сведения о клубах, контрактах, фотографии и сезонная статистика могут быть неполными или устаревшими. Это не live-источник данных.

## Как работает сборка

- Исходный архив: `TransferLab_RESTORED_2026-11-16.zip`.
- Сборщик: `scripts/prepare.py` — создаёт `_site/index.html` и применяет исправления интерфейса.
- Стили: `assets/site.css`; улучшения доступности: `assets/site.js`.
- Автотест: `scripts/smoke.py`, проверяет поиск, профиль, сортировку и фильтрацию в браузере.
- Публикация: `.github/workflows/pages.yml`, GitHub Actions.

## Публикация

В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
В Actions запустите **Build and publish TransferLab** через **Run workflow**, если публикация не начнётся сама.

После успешного релиза сайт будет доступен по адресу: `https://gosha-tech.github.io/transferlab/`.

## Актуальность данных

Ежедневное автоматическое обновление реальной статистики **пока не подключено**. Для него нужен API-ключ провайдера футбольных данных, покрывающего нужные соревнования, и отдельная проверенная задача обновления. Без неё нельзя обещать свежие результаты или автоматически подтверждать трансферы.

Не вносите секреты API в публичные исходники или `index.html`. Используйте **Settings → Secrets and variables → Actions**.

## Ежедневное обновление статистики и турниров

1. Получите ключ на https://dashboard.api-football.com/
2. Откройте https://github.com/gosha-tech/transferlab/settings/secrets/actions
3. Нажмите New repository secret и укажите имя API_FOOTBALL_KEY (строго без пробелов).
4. Вставьте ключ в значение секрета. Не публикуйте ключ в README, сайте или чате.
5. Откройте https://github.com/gosha-tech/transferlab/actions/workflows/pages.yml и запустите Build and publish TransferLab через Run workflow. Далее запуск ежедневный, в 07:17 UTC.

Задача извлекает статистику API-Football по турнирам (АПЛ, ЛЧ, кубки, другие лиги), сохраняет data/live.json и встраивает данные в HTML сайта до его публикации. Новые игроки получают устойчивый API ID, поэтому дополнительные профили сохраняются при повторном обновлении.

Проверка: оба задания build и deploy должны завершиться с зелёными галочками. В профиле игрока можно выбрать соревнование. Отсутствующие показатели остаются пустыми, неполное покрытие прямо помечено.

Ограничение бесплатного API: 100 запросов в день и первые 3 страницы игроков для турнира; это НЕ полное покрытие чемпионатов и всех кубков. Для полного импорта требуется подходящий тариф и историческая дозагрузка.
Документация: https://www.api-football.com/documentation-v3

## Важно: текущая статистика 2026/27 требует платного доступа

По состоянию на 17 ноября 2026 года файл `data/live.json` ещё имеет статус `awaiting_api_key` и пустую коллекцию `records` — это **не** актуальная статистика.

API-Football: в 2026 году бесплатный доступ охватывает сезоны 2022–2024 и первые 3 страницы статистики игроков, поэтому **Free-ключ не поможет загрузить все показатели 2026/27**. Для текущего сезона и полной пагинации требуется оплачиваемый план с соответствующим покрытием. Проверяйте актуальные условия в https://www.api-football.com/pricing.

Сборщик уже поддерживает платный план: по умолчанию до 100 страниц на турнир, до 1400 запросов за запуск и паузу 0,6 секунды. При необходимости регулируйте их в `Settings → Secrets and variables → Actions → Variables` как `API_MAX_PAGES`, `API_REQUEST_BUDGET`, `API_REQUEST_INTERVAL_SECONDS`.

Единственное необходимое действие владельца: оформить соответствующий доступ в API-Football и сохранить ключ в GitHub Secret `API_FOOTBALL_KEY`. Не вставлять ключ в публичные файлы. После этого `Actions → Build and publish TransferLab → Run workflow`; проверить число покрытых игроков и отметку времени на сайте.

Даже платный API не гарантирует показатели для всех игроков: отсутствие минут, xG, xA или фото у источника должно оставаться незаполненным. Для оценок без достоверной статистики используется `Нет данных`.


## Бесплатные ежедневные данные (работают без оплаты)

TransferLab 6.0 использует три бесплатных источника **только в пределах их фактического покрытия**:

- [OpenFootball / football.json](https://github.com/openfootball/football.json): результаты/счёт матчей сезона 2026/27 для доступных лиг; **без статистики отдельных футболистов**. База файла пересобирается ежедневно, но исходные данные могут отставать — смотрите дату последнего матча.
- [TheSportsDB Free API](https://www.thesportsdb.com/docs/api): поиск и проверка игроков по уникальному ID / точной дате рождения, портреты с явно указанной лицензией Creative Commons и ограниченные строки статистики игроков. Бесплатный API возвращает только часть статистики, поэтому она ВСЕГДА помечена как неполная. Из-за ограничений скорости профили проверяются по очереди в разных ежедневных запусках.
- [football-data.org](https://www.football-data.org/pricing): при добавлении бесплатного секрета `FOOTBALL_DATA_ORG_KEY` дополнительно загружаются разрешённые провайдером результаты матчей. Бесплатный тариф **не содержит полной личной статистики футболистов**.

Ежедневная задача GitHub Actions автоматически запускает `scripts/sync_free.py`, сохраняет `data/free_sources.json`, встраивает полученные результаты в `index.html` и публикует новую версию. Платный API-Football для этого **не нужен**. Его поддержка остаётся опциональной — только если владелец когда-нибудь захочет более полную персональную статистику.

Точные результаты показываются в разделе «Последние результаты матчей». В профиле игрока опубликованные данные по отдельному соревнованию не считаются полной статистикой сезона, если бесплатный источник не предоставил все матчи. Нельзя превращать голы команды в голы футболиста, обновлять клуб по одному архивному ответу или показывать отсутствующие значения как нули.

Фотографии TheSportsDB **не публикуются автоматически только на основании флага Creative Commons**: требуется отдельная проверка автора, конкретного файла и лицензии изображения. Входящие ссылки и сведения об авторе могут сохраняться в данных, но неизвестные права не считаются разрешением.

**Фактическая полнота загрузки:** в `data/free_sources.json` указаны время последнего успешного обращения, проверенные профили, число игроков со статистикой текущего сезона и список ошибок. Успешная публикация GitHub Pages не равна полной персональной статистике.
